# 条款义务拆分器 - Clause Obligation Splitter

## 任务目标

从给定的法规条款/公司制度文本中，**原子化拆分**并提取所有合规义务要素，生成结构化数据。每条义务必须单独成记录，不允许合并多个动作。

## 核心原则

1. **原子化拆分**：如果一个条款包含多个动词（如"建立、完善并执行"），必须拆解为多条独立的义务记录。一个动词对应一条记录。
2. **上下文溯源补全**：如果触发条件或主体仅在段首出现，后续分句提取时必须根据逻辑补全，确保每条记录语义完整可独立理解。
3. **不省略任何义务**：即使条款长，也要逐条拆分所有动作，不能遗漏。

## 提取Schema定义

必须严格按照以下YAML结构输出：

| 字段                            | 说明                                                                                                                                          | 示例                                                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **触发义务条件**          | 触发该义务的时间/地点/场景/前提，若无明确条件则填 "/"                                                                                         | `"在符合监管要求基础上"`                                                                                              |
| **义务主体**              | 执行动作的完整机构或角色名（保留所有限定定语）。只填写你认为概率最高的主体                                                                    | `"成员公司"` `"董事会"` `"集团风险管理部门"`                                                                      |
| **义务客体**              | 动作指向的对象（机构/人/事务），若无则填 "/"                                                                                                  | `"辖内风险管理"`                                                                                                      |
| **义务内容.义务规则**     | 枚举值，只能是`应当` 或 `禁止`                                                                                                            | `应当`                                                                                                                |
| **义务内容.义务动作**     | 核心动词（单个动词）                                                                                                                          | `"负责"` `"建立"` `"承担"` `"报告"`                                                                             |
| **义务内容.义务事项**     | 动词指向的具体业务内容（补充说明动作对象）                                                                                                    | `"辖内风险管理的独立决策"`                                                                                            |

## 特殊处理规则（重要！）

### ⚠️ 必须不拆分的条款类型

以下类型的条款**绝对不需要拆分**，`是否拆分`字段填 '否'，所有其他字段填 "/"：

#### 1. 名词解释/定义类

- 句式模式："XX是指YY"、"XX定义为YY"、"XX即YY"
- 示例："不为公众所知悉，是指该信息不为其所属领域的相关人员普遍知悉和容易获得。"
- 示例："商业秘密，是指不为公众所知悉、具有商业价值并经权利人采取相应保密措施的技术信息、经营信息等商业信息。"

#### 2. 范围列举/界定类（重点！）

- 句式模式："下述信息...属于xx"、"下述信息...不属于xx"、"xx包括：1...2...3..."
- **这类条款的核心功能是界定范围，而非规定具体义务动作**
- 判断标准：条款中**没有明确的义务主体执行具体动作**（如"应当建立"、"禁止披露"），只是列举哪些信息属于或不属于某类
- 示例1（属于）："下述信息符合第五十一条规定的商业秘密定义的，属于公司商业秘密：（一）重要会议信息... （二）公司战略信息..."
- 示例2（不属于）："下述信息不属于商业秘密：（一）信息为其所属技术或者经济领域的人的一般常识或者行业惯例；..."
- 这类条款即使包含"属于"、"包括"等动词，也只是**定义性描述**，不是合规义务，**不能拆分**

**⚠️ 重要区分：分类规定 vs 范围列举**

以下情况**不是**纯范围列举，而应正常拆分提取义务：

- 句式模式："XX分为A、B、C三级"、"XX应当分为..."、"公司应当将XX分类为..."
- 判断标准：条款中存在**明确的义务主体**（如"公司"）和**明确的义务动作**（如"分为"、"分类"），且该动作是公司对某事物进行的分类管理行为
- 示例（需要拆分）："根据公司商业秘密的价值、内容的敏感程度、接触范围等因素，商业秘密分为绝密、机密、秘密三级："
  - 义务主体：公司（隐含）
  - 义务动作：分类/分为
  - 义务事项：绝密、机密、秘密三级商业秘密
  - 触发义务条件：根据公司商业秘密的价值、内容的敏感程度、接触范围等因素
  - 示例（需要拆分）："公司应当将员工信息分为普通、重要、核心三级管理"
    - 义务主体：公司
    - 义务动作：分为/分类
    - 义务事项：员工信息三级管理

**判断关键**：如果句子表达的是"某主体应当/需要对某事物进行分类管理"，则属于合规业务，需要拆分；如果句子只是"某些信息属于/不属于某类别"，则属于范围界定，不需要拆分。

#### 3. 纯说明性/解释性条款

- 句式模式："XX即指"、"XX意为"、"以上所称XX包括"
- 这类条款是对前文术语的进一步解释说明

### 判断流程（按顺序判断）

```
1.该条款是否有明确的义务主体？（谁应当/禁止做某事；"公司分为A、B、C三级"中"公司"为隐含主体）
  ↓ 否 → 进入第2步
  ↓ 是 → 进入第2步
2.该条款是否有明确的义务动作？（应当/禁止做什么具体事情；"分为"、"分类"是动作）
  ↓ 否 → 是否拆分：否
  ↓ 是 → 进入第3步
3.该条款是否只是范围列举/定义界定？（如"下述信息属于/不属于XX"，没有管理动作）
  ↓ 是 → 是否拆分：否
  ↓ 否 → 进入第4步
4.该条款是否为分类规定？（如"XX分为A、B、C三级"，有明确主体执行分类动作）
  ↓ 是 → 是否拆分：是（提取分类义务）
  ↓ 否 → 进入第5步
5.需要进行义务拆分 → 是否拆分：是
```

### 输出规则

- **如果 `是否拆分` 填 '否'**：所有其他字段必须填 "/"（条款出处字段除外，必须填写条款编号和核心原句），**但仍必须输出这条记录**
- **如果 `是否拆分` 填 '是'**：按正常流程拆分提取义务记录
- **⚠️ 重要：每条输入的条款都必须有对应的输出记录！不能跳过或省略任何条款！**

## 判断规则

1. **义务规则判定**：条款中若出现"负责"、"承担"、"建立"、"应当"、"必须"、"需"、"要"、"须"等词汇，义务规则统一判定为 **应当**。出现"不得"、"禁止"、"严禁"则判定为 **禁止**。
2. **严禁合并**：不要将"负责A和B"写在一起，请拆分为"负责A"和"负责B"两条记录。一个动词对应一条记录。
3. **多个动词拆分为多条**：每遇到一个独立的谓语动词，都要拆分为一条新记录。

## 句法逻辑分析与义务主体判定

### 核心原则

必须根据**语义逻辑**确定每个动作的实际执行者，不能简单地将所有动作都归给句首主语。

### 典型情况处理

**情况1：多层委托/设置结构**

- 原句模式：`[上级主体] + 须 + [动作1:指定/设立/成立] + [下级机构/部门] + ， + [下级机构] + [动作2:承担/负责/对接] + ...`
- 判定方式：`动作1`的主体是**上级主体**，`动作2及后续`的主体是**下级机构/部门**

**示例分析**：

> 成员公司须指定辖内全面风险管理的统筹部门，承担辖内全面风险管理体系建设的日常管理牵头责任。

- 动词"指定" → 主体：**成员公司**
- 动词"承担" → 主体：**辖内全面风险管理的统筹部门**（因为是被指定的部门来承担责任）

**情况2：并列动作结构**

- 原句模式：`[主体] + 应当 + [动作1] + [宾语1] + 并 + [动作2] + [宾语2]`
- 判定方式：所有并列动作的主体都是同一个主语

**示例分析**：

> 成员公司应当建立健全制度，并执行风险管理流程。

- 动词"建立健全" → 主体：成员公司
- 动词"执行" → 主体：成员公司

### 分析步骤

1. 先找出所有谓语动词，标记位置
2. 分析每个动词之前最近的名词性成分（机构/部门/角色）
3. 根据句法结构判断谁是动作的实际发出者
4. 如果不确定，遵循"就近原则"：动词的主体是它前面最近出现的机构

### 歧义处理

当句子存在多种合理解读，不同解读对应不同的义务主体/客体归属时：

1. **必须在YAML输出前先用自然语言说明整体歧义**
2. 在每条有歧义的记录中，**歧义说明**字段写明歧义点：
   - 写出两种可能的理解
   - 说明为什么会产生歧义
   - 说明你选择当前主体/客体的理由
   - 无歧义则填"无歧义"
3. **义务主体**字段只填写你认为概率最高的那个值，不混合多个可能
4. 所有结果都在同一个YAML文件中

**歧义标注示例**：

```yaml
- 记录3:
    触发义务条件: 对每类风险（不涉及的风险类别除外）
    义务主体: 成员公司
    义务客体: /
    义务内容:
      义务规则: 应当
      义务动作: 承担
      义务事项: 各类风险及细分领域管理的直接责任
    条款出处:
      条款编号: 第十四条第（三）项
      条款核心原句: 成员公司须...，承担各类风险及细分领域管理的直接责任。
    歧义说明: 存在两种解读：(1) 并列结构，主体是成员公司（当前选择）；(2) 多层结构，主体应为辖内统筹管理的职能部门，即成员公司明确了该部门后由其承担责任。两种语法都正确。
    是否拆分: 是
```

这样业务方后续处理时就能看到歧义说明，自行判断选择。
